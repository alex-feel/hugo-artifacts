# github-profile module test suite

Node build-output assertions for `shortcodes/github-profile`, pinning a defect in the headline metric strip's separators that only surfaces after Hugo's `--minify` pass runs. The module ships no client-side JavaScript, so there is no browser behavior to test and the suite carries no Playwright dependency; every assertion reads bytes straight out of a published `index.html`.

**This is the only test suite in this repository that builds its fixture with `hugo --minify`, and that matters because the defect it pins is invisible without it.** Hugo's minifier collapses every run of whitespace to a single character and then deletes any whitespace that immediately follows it, even across a tag boundary, so a newline-plus-indent sitting just inside a wrapper's closing tag can eat the LEADING space of the separator element that follows it. A plain build's pretty-printed whitespace still contains that same newline-plus-indent, but nothing depends on it there, so a plain-only suite reads a well-formed strip and never sees the byte the minifier deletes. Every spec here therefore reads two builds of the same fixture rather than one, and the assertions that matter most read the minified tree specifically.

## Running

```bash
bash shortcodes/github-profile/test/run-tests.sh
```

or, on Windows:

```text
shortcodes\github-profile\test\run-tests.cmd
```

Both runners perform the repository's pre-launch Hugo process check, purge stale output, build the fixture THREE TIMES from the same fixture directory -- plain, with `--minify`, and origin-backed with `fixture/origin.toml` layered on -- fail hard on any `deprecat`, `ERROR`, or `found no layout file` line in any build log, and then run the assertions. The runners start `serve-origin.mjs` (a static origin over the committed `fixture-origin/` corpus, on `127.0.0.1:1717`) around the third build and stop it afterward.

> **These builds need loopback network access only.** The fixture shadows the module's remote-fetch partial (`layouts/_partials/github-profile/fetch.html`) with one that reads a canned GraphQL snapshot from `data/github-profile-fetch.json`, so the first two builds are fully offline: their pages request `avatar="hotlink"` (or `avatar="none"`) and nothing fetches. The third build is the ONE that fetches -- a single avatar image from the suite's own origin -- because the fetch success arm of the shared avatar partial is guarded template code of its own, including the `templates.Exists` probe for the OPTIONAL `url-retirement` sibling whose false arm only a site importing github-profile ALONE can take. The registration side of that same arm -- the published copies reaching the `url-retirement` manifest where a site imports both modules -- is covered by the cross-module composition suite (`modules/test-composition/`).

Re-run the assertions alone against existing builds by setting the same environment variables the runner exports and calling `npm test` directly:

```bash
FIXTURE_PUBLIC=fixture/public/normal \
FIXTURE_PUBLIC_MINIFIED=fixture/public/minified \
FIXTURE_PUBLIC_ORIGIN=fixture/public/origin \
HUGO_BUILD_LOG=hugo-build.log \
HUGO_BUILD_LOG_MINIFIED=hugo-build-minified.log \
HUGO_BUILD_LOG_ORIGIN=hugo-build-origin.log \
npm test
```

## Three builds, one fixture

| Build | Destination | Extra flags | What it proves |
| --- | --- | --- | --- |
| normal | `fixture/public/normal` | none | The control. Whatever the minifier does to the published bytes, a reader must get the same sentence out of either tree, and only the plain tree proves the markup was well-formed before the minifier touched it -- if the plain build ever failed the text-layer assertions, the defect would be in the templates rather than in `--minify`. |
| minified | `fixture/public/minified` | `--minify` | Where the defect actually lives. The note separator's leading space and the calendar summary's total-to-window separating space only vanish here, because only here does the minifier delete the whitespace that a reformatted wrapper's closing tag leaves behind. |
| origin | `fixture/public/origin` | `--config hugo.toml,origin.toml` | The fetch success arm, on a site importing github-profile alone. `origin.toml` allow-lists the loopback origin and names it in a param the fetch seam reads, so the `avatar-fetch/` page's `origin-dev` login resolves and the shared avatar partial really calls `resources.GetRemote` -- and really takes the false arm of its `url-retirement` guard, which every fixture importing that module leaves unrendered. |

## The fixture's shadowed fetch seam

The module fetches live GitHub GraphQL data at build time and needs `HUGO_GITHUB_TOKEN` to do it; this fixture is fully offline instead. `fixture/layouts/_partials/github-profile/fetch.html` shadows the module's own partial of the same path and returns a canned dict read from `fixture/data/github-profile-fetch.json` (a 1361-line GraphQL snapshot) via `index hugo.Data "github-profile-fetch"` rather than calling `resources.GetRemote`. Every other partial in the chain -- derive, render, and every section template -- runs for real, which is the whole point: the suite asserts the markup those real templates emit, not a stub of it. A login other than the canned ones returns `apiOk false` with `degradedReason "not-found"`, and a missing data file raises `errorf` rather than degrading silently, because a silent degradation there would make every assertion in the suite pass vacuously against the identity chip. A second canned login, `origin-dev`, exists for the origin-backed build alone: the seam answers it with a minimal identity whose `avatarUrl` points at the suite's own origin, and only when `origin.toml`'s param names that origin -- so the same page degrades to the identity chip, silently, in the two offline builds.

The seam serves the module's full return contract, the authorship fields included: under `language-scope="worked-in"` it returns the canned `authorship` map (nameWithOwner to the person's own default-branch commit count) with `authorshipOk true`, exactly as the module's own fetch partial would after its authorship request resolved. One degradation no login can select -- a FAILED authorship request on an otherwise healthy profile -- is selected by the calling page instead: `github_profile_fixture_authorship_fail = true` in front matter makes the seam report `authorshipOk false` with an empty map, which is the shape the module partial returns after its retries are exhausted.

The seam has one blind spot, and `fixture/layouts/query-shape.html` is what covers it: shadowing `fetch.html` also removes `build-query.html`'s only caller, so the requests the module would actually send are never built. That layout calls the real partial for all three request kinds and publishes what it returns, base64-encoded, on its own page. It is one reason the fixture builds eight pages rather than one -- `index.html` for the default configuration, `languages-worked-in/` for the opt-in scope, `languages-worked-in-degraded/` for that scope after a failed authorship request, `query-shape/` for the requests themselves, `avatar-none/` for the image-free baseline of the organization surfaces, `rollup-limited/` for a rollup cap below the canned owner count, `limits-off/` for both list caps at `0`, and `avatar-fetch/` for the fetch success arm the origin-backed build renders -- each configuration on its own page so the home-page specs keep seeing exactly one widget in every class they address.

The canned values were chosen to exercise every branch the headline strip and calendar summary render: commits `1842` formats to `1.8k`; `mergedPrCount 1289` formats to `1.3k` and is non-negative, so the merged-PRs branch wins over the plain PR-count branch; `repositoriesContributedTo.totalCount 20` is read against only 9 returned nodes, proving the external-repositories metric reads the total count rather than the node-list length (and feeding the contributed list's `and 11 more` remainder note); `organizations.totalCount 6` against 4 returned nodes puts the same device under the membership list's note; the byRepo owners carry `avatarUrl` values with three deliberate gaps -- `solo-maintainer` (the rollup placeholder subject), both `open-fixture` owners in the commit list (the fill-from-a-later-list subject) -- and the fourth membership, `quiet-collective`, carries none (the membership placeholder subject), deviations a real response would not produce (the scalar is non-null; only whole nodes go missing) and which `10-query-shape.spec.js` therefore pins by exact enumeration so they stay deliberate; 5 distinct organization owners produce `externalOrgs 5`; the calendar spans 14 weeks (98 days) with 63 active days but only 55 of them inside the trailing 90-day window, exercising the truncation branch that the recency metric reads; `restrictedContributionsCount 7934` formats to the grouped `7,934` that the floor note and its separator sit next to, which is the defect site; `show-rank` resolves to level `A+` at percentile `8.0` -- a percentile landing exactly ON a whole number, which is what makes the one-decimal rendering provable, and which is why `followers` is 85: it is the only rank input the module never displays, so it can be tuned to place the percentile without disturbing any other assertion, and 8.0 sits in the same sub-12.5 bucket as the 7.4 it replaced, so the level is unchanged; the current streak is `12` days and the longest is `21`. The language byte counts are cut to the same standard. The OWNED repositories -- the default scope, and the whole of what the home page's row measures -- sum to exactly 1,000,000 so the shares are exact, and they produce values landing ON a whole number (Python `40.0%`, TypeScript `25.0%`, Go `15.0%`, Shell `5.0%`), values ROUNDING onto one (HTML from 9.58, Lua from 2.17), ordinary one-decimal values, and one language under 0.05% of the total that renders `0.0%` from inside the top eight while a smaller ninth is cut by the cap. That last group is the point: the counts that shipped gave every language a nonzero decimal, so the row a broken template published was byte-identical to the row a correct one did, and no assertion here could have told them apart. No value sits on an exact half at the rounding step either, because Hugo's `math.Round` rounds a half away from zero where several other languages round it to even, and a fixture value on `x.x5` would encode one tie-break as an expected string.

The two blocks of repositories the person does not own answer different questions, exactly as the query asks them. `repositoriesContributedTo` keeps all four contribution types and carries no language counts at all; `codeContributedTo` narrows to `COMMIT` and `PULL_REQUEST` and carries the language counts plus each default branch's total commit count, the denominator of the authorship ratio whose numerators live in the top-level `authorship` map. `issue-only-org/tracker` sits in the first and not the second -- 4,000,000 bytes of Kotlin, a language in no other repository here, so it would have been the SECOND largest share on the strength of one filed issue and its absence is one exact assertion rather than a judgement about a share that moved. `mega-org/monolith` sits in both, at 10,489,000 bytes: ten times everything the person owns put together, at authorship 0 of 4143 -- the unmerged-pull-request shape -- so the weighted opt-in row must give it NOTHING while an unweighted sum would top the row with its Go. The remaining code-contributed repositories each carry one weighting case: `fixture-labs/toolkit` a proportional partial ratio (1200/2000), `solo-maintainer/gadget` a second one (10/20), `another-org/pipeline` full authorship (30/30) on the primary page and a clamped window ratio (50 over 30) on the degraded one, `fixture-labs/docs-site` the per-repository numerator fallback (absent from the authorship map, window count 40 over branch total 100), `open-fixture/rebase-lab` the present-zero rule (authorship entry 0 beside a window count of 25 over branch total 50, so its unique Zig is absent from the primary row and enters the degraded one), and `quiet-user/snippets` the no-usable-ratio exclusion (500,000 bytes of Nix, unique to it, behind a null `defaultBranchRef`). The weighted worked-in corpus lands on exactly 1,299,000 bytes, and the degraded page's window-count corpus on 1,091,800.

The one value the fixture cannot pin is `tenureYears` in the identity section, computed as `now - createdAt`, so no spec here asserts it.
