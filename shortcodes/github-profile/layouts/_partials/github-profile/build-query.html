{{/* Builds the JSON request body for a GitHub GraphQL API call. Inputs (context dict): - .kind (string) "snapshot" for the single full-profile query, "years" for the all-time follow-up query, or "authorship" for the per-repository default-branch authorship counts behind the worked-in language scope. - .login (string) For kinds "snapshot" and "years": GitHub login, passed as the $login GraphQL variable (never string-interpolated into the query text, so no escaping concerns). - .years (slice) For kind "years": the contributionYears values from the snapshot response (JSON-decoded numbers). One aliased contributionsCollection block is emitted per year; each block spans one calendar year (January 1 through December 31), which stays inside the API's hard 1-year limit on the from/to span. - .uid (string) For kind "authorship": the user's global node ID from the snapshot, passed as the $uid GraphQL variable. The history author filter takes a CommitAuthor input object ({id, emails}) with no login field, so the node ID is the only way to name the person. - .repos (slice) For kind "authorship": nameWithOwner strings from the snapshot's codeContributedTo nodes. Each valid entry yields one aliased repository() block named r, where is the entry's position in THIS slice -- an invalid entry is skipped WITHOUT renumbering, so the caller can always decode an alias back to a repository by indexing the same slice it passed in. Owner and name are validated against GitHub's naming rules before interpolation because, unlike the login above, they are remote-derived text placed into the query string. Returns: the JSON body string for resources.GetRemote (jsonify handles all escaping, including the newlines inside the query text). Design notes: - The snapshot is ONE static query regardless of which sections render: the whole query empirically costs 3 rate-limit points, a static shape keeps the response cacheable per user, and section toggles then only affect rendering, never fetching. - The snapshot queries the user through TWO aliased user() fields (core and byRepo) in the same POST. The four *ContributionsByRepository lists are the only place where a REPOSITORY object hangs off a fully non-null path (ContributionsCollection! -> [XContributionsByRepository!]! -> repository: Repository!), so a repository the token may not read -- a fine-grained token an organization's policy rejects, or SAML enforcement -- cannot be nulled in isolation there: the null propagates up to the whole user object. Isolating those lists behind their own aliased user field stops the propagation at that alias, so the core block still resolves and the widget renders everything except the per-organization rollup. Everywhere else, repositories and organizations arrive as items of NULLABLE node lists ([Repository], [Organization], [PinnableItem]), where a restricted entry nulls only itself. (Other requested chains are non-null too -- the contribution calendar is one -- but they carry no access-controlled object, so nothing in them can be withheld.) The split is data-equivalent to the single-block query at identical rate-limit cost (verified empirically). - repositoriesContributedTo is requested TWICE, under different contributionTypes, because two sections want different questions answered. The unaliased block answers "which repositories has this person worked in", so it keeps all four contribution types and feeds the contributed list and the external-footprint counts. The codeContributedTo alias answers "which repositories has this person written CODE in", so it narrows to COMMIT and PULL_REQUEST and carries the language byte counts plus each default branch's total commit count (the authorship ratio's denominator). Filing an issue enrolls a repository in the first and not in the second, which is the whole point: a language chart built from the first attributes a 22 MB codebase to someone whose only contribution to it was one issue. Measured against the live API, the split itself costs nothing -- the languages sub-selection MOVED between two connections of the same width rather than being duplicated -- and the snapshot costs 3 rate-limit points at nodeCount 2432, one point of which is the default-branch history sub-selection nested under the 100-node codeContributedTo connection. - contributionsCollection is called without from/to in the snapshot, which yields the rolling ~1-year window ending now -- the same window GitHub's own profile page shows. - The four *ContributionsByRepository lists cap at maxRepositories: 100 (the API's hard ceiling); for extremely prolific accounts the per-organization rollup therefore covers the top 100 repositories per contribution type within the window. Each list's owner block carries avatarUrl(size: 64) for the rollup's avatar images -- a scalar on the already-selected owner node, so it adds no connection and leaves the API's node-count cost formula unchanged. - The all-time totals cannot be part of the snapshot because the year list is only known from the snapshot's contributionYears; the "years" kind exists for that second, opt-in (history="all") round trip. - The "authorship" kind exists for the same reason: which repositories to ask about is only known from the snapshot's codeContributedTo list. It is issued only under language-scope="worked-in", and it carries the NUMERATOR of the per-repository authorship ratio (the person's own default-branch commits, via history(author: {id})); the DENOMINATOR (the branch's total commit count) travels in the snapshot itself, under each codeContributedTo node's defaultBranchRef. Measured cost: 1 rate-limit point at nodeCount 3 for 3 repositories; the node count scales linearly with the repository count, and the API's cost formula (one history connection per aliased block, summed and divided by 100) keeps even the 100-repository ceiling at 1 point. */}} {{- $kind := .kind -}} {{- $login := .login -}} {{- $years := .years | default (slice) -}} {{- $uid := .uid | default "" -}} {{- $repos := .repos | default (slice) -}} {{- $query := "" -}} {{- $variables := dict "login" $login -}} {{- if eq $kind "snapshot" -}} {{- $query = `query($login: String!) { core: user(login: $login) { login id databaseId name bio company location pronouns websiteUrl avatarUrl(size: 200) url createdAt isHireable status { message emoji } followers { totalCount } following { totalCount } socialAccounts(first: 10) { nodes { provider displayName url } } organizations(first: 12) { totalCount nodes { login name url avatarUrl(size: 64) } } pinnedItems(first: 6, types: [REPOSITORY]) { nodes { __typename ... on Repository { nameWithOwner description url stargazerCount forkCount primaryLanguage { name } } } } repositories(first: 100, ownerAffiliations: [OWNER], isFork: false, orderBy: {field: STARGAZERS, direction: DESC}) { totalCount nodes { nameWithOwner stargazerCount languages(first: 10, orderBy: {field: SIZE, direction: DESC}) { edges { size node { name } } } } } contributionsCollection { totalCommitContributions totalIssueContributions totalPullRequestContributions totalPullRequestReviewContributions totalRepositoryContributions restrictedContributionsCount contributionYears startedAt endedAt contributionCalendar { totalContributions weeks { firstDay contributionDays { date contributionCount contributionLevel weekday } } } } repositoriesContributedTo(first: 100, includeUserRepositories: false, contributionTypes: [COMMIT, ISSUE, PULL_REQUEST, PULL_REQUEST_REVIEW]) { totalCount nodes { nameWithOwner description url stargazerCount forkCount primaryLanguage { name } owner { login __typename } } } codeContributedTo: repositoriesContributedTo(first: 100, includeUserRepositories: false, contributionTypes: [COMMIT, PULL_REQUEST]) { nodes { nameWithOwner languages(first: 10, orderBy: {field: SIZE, direction: DESC}) { edges { size node { name } } } defaultBranchRef { target { ... on Commit { all: history(first: 1) { totalCount } } } } } } } byRepo: user(login: $login) { contributionsCollection { commitContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename avatarUrl(size: 64) } } contributions(first: 1) { totalCount } } issueContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename avatarUrl(size: 64) } } contributions(first: 1) { totalCount } } pullRequestContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename avatarUrl(size: 64) } } contributions(first: 1) { totalCount } } pullRequestReviewContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename avatarUrl(size: 64) } } contributions(first: 1) { totalCount } } } } }` -}} {{- else if eq $kind "authorship" -}} {{/* kind "authorship": one aliased repository() block per codeContributedTo entry, asking for the person's own commit count on the default branch (the ratio's numerator). The alias index is the entry's position in the caller's .repos slice, and a rejected entry is skipped WITHOUT renumbering, so the caller decodes aliases by indexing that same slice. Owner and repository names are remote-derived text interpolated into the query string, so both are validated against GitHub's naming rules first: owners follow the login shape (alphanumerics and inner hyphens, at most 39 characters) and repository names allow alphanumerics, hyphens, underscores and periods, at most 100 characters. The validated character sets contain nothing GraphQL string syntax treats specially. */}} {{- $blocks := slice -}} {{- range $i, $repo := $repos -}} {{- $parts := split (printf "%v" $repo) "/" -}} {{- if eq (len $parts) 2 -}} {{- $owner := index $parts 0 -}} {{- $name := index $parts 1 -}} {{- if and (findRE `^[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,37}[a-zA-Z0-9])?$` $owner) (findRE `^[A-Za-z0-9._-]{1,100}$` $name) -}} {{- $blocks = $blocks | append (printf `r%d: repository(owner: "%s", name: "%s") { defaultBranchRef { target { ... on Commit { mine: history(first: 1, author: {id: $uid}) { totalCount } } } } }` $i $owner $name) -}} {{- end -}} {{- end -}} {{- end -}} {{- $query = printf "query($uid: ID!) { %s }" (delimit $blocks " ") -}} {{- $variables = dict "uid" $uid -}} {{- else -}} {{/* kind "years": one aliased per-calendar-year block per contributionYears entry, count fields only. JSON-decoded numbers arrive as floats, so each year is cast to int before formatting; the cast is try-wrapped so a malformed remote value skips its block instead of failing the build. */}} {{- $blocks := slice -}} {{- range $years -}} {{- $y := 0 -}} {{- with try (int .) -}} {{- with .Value -}} {{- $y = . -}} {{- end -}} {{- end -}} {{- if and (ge $y 2005) (le $y 2100) -}} {{- $blocks = $blocks | append (printf `y%d: contributionsCollection(from: "%d-01-01T00:00:00Z", to: "%d-12-31T23:59:59Z") { totalCommitContributions totalIssueContributions totalPullRequestContributions totalPullRequestReviewContributions totalRepositoryContributions restrictedContributionsCount }` $y $y $y) -}} {{- end -}} {{- end -}} {{- $query = printf "query($login: String!) { user(login: $login) { %s } }" (delimit $blocks " ") -}} {{- end -}} {{- return (jsonify (dict "query" $query "variables" $variables)) -}}
