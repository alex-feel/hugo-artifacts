{{/* Builds the JSON request body for a GitHub GraphQL API call. Inputs (context dict): - .kind (string) "snapshot" for the single full-profile query, or "years" for the all-time follow-up query. - .login (string) GitHub login, passed as the $login GraphQL variable (never string-interpolated into the query text, so no escaping concerns). - .years (slice) For kind "years": the contributionYears values from the snapshot response (JSON-decoded numbers). One aliased contributionsCollection block is emitted per year; each block spans one calendar year (January 1 through December 31), which stays inside the API's hard 1-year limit on the from/to span. Returns: the JSON body string for resources.GetRemote (jsonify handles all escaping, including the newlines inside the query text). Design notes: - The snapshot is ONE static query regardless of which sections render: the whole query empirically costs 2 rate-limit points, a static shape keeps the response cacheable per user, and section toggles then only affect rendering, never fetching. - The snapshot queries the user through TWO aliased user() fields (core and byRepo) in the same POST. The four *ContributionsByRepository lists are the only place where a REPOSITORY object hangs off a fully non-null path (ContributionsCollection! -> [XContributionsByRepository!]! -> repository: Repository!), so a repository the token may not read -- a fine-grained token an organization's policy rejects, or SAML enforcement -- cannot be nulled in isolation there: the null propagates up to the whole user object. Isolating those lists behind their own aliased user field stops the propagation at that alias, so the core block still resolves and the widget renders everything except the per-organization rollup. Everywhere else, repositories and organizations arrive as items of NULLABLE node lists ([Repository], [Organization], [PinnableItem]), where a restricted entry nulls only itself. (Other requested chains are non-null too -- the contribution calendar is one -- but they carry no access-controlled object, so nothing in them can be withheld.) The split is data-equivalent to the single-block query at identical rate-limit cost (verified empirically). - repositoriesContributedTo is requested TWICE, under different contributionTypes, because two sections want different questions answered. The unaliased block answers "which repositories has this person worked in", so it keeps all four contribution types and feeds the contributed list and the external-footprint counts. The codeContributedTo alias answers "which repositories has this person written CODE in", so it narrows to COMMIT and PULL_REQUEST and carries nothing but the language byte counts. Filing an issue enrolls a repository in the first and not in the second, which is the whole point: a language chart built from the first attributes a 22 MB codebase to someone whose only contribution to it was one issue. Measured against the live API, the split costs nothing: the whole snapshot stays at 2 rate-limit points (nodeCount 2232 -> 2332), because the languages sub-selection MOVED between two connections of the same width rather than being duplicated. - contributionsCollection is called without from/to in the snapshot, which yields the rolling ~1-year window ending now -- the same window GitHub's own profile page shows. - The four *ContributionsByRepository lists cap at maxRepositories: 100 (the API's hard ceiling); for extremely prolific accounts the per-organization rollup therefore covers the top 100 repositories per contribution type within the window. - The all-time totals cannot be part of the snapshot because the year list is only known from the snapshot's contributionYears; the "years" kind exists for that second, opt-in (history="all") round trip. */}} {{- $kind := .kind -}} {{- $login := .login -}} {{- $years := .years | default (slice) -}} {{- $query := "" -}} {{- if eq $kind "snapshot" -}} {{- $query = `query($login: String!) { core: user(login: $login) { login databaseId name bio company location pronouns websiteUrl avatarUrl(size: 200) url createdAt isHireable status { message emoji } followers { totalCount } following { totalCount } socialAccounts(first: 10) { nodes { provider displayName url } } organizations(first: 12) { totalCount nodes { login name url avatarUrl(size: 64) } } pinnedItems(first: 6, types: [REPOSITORY]) { nodes { __typename ... on Repository { nameWithOwner description url stargazerCount forkCount primaryLanguage { name } } } } repositories(first: 100, ownerAffiliations: [OWNER], isFork: false, orderBy: {field: STARGAZERS, direction: DESC}) { totalCount nodes { nameWithOwner stargazerCount languages(first: 10, orderBy: {field: SIZE, direction: DESC}) { edges { size node { name } } } } } contributionsCollection { totalCommitContributions totalIssueContributions totalPullRequestContributions totalPullRequestReviewContributions totalRepositoryContributions restrictedContributionsCount contributionYears startedAt endedAt contributionCalendar { totalContributions weeks { firstDay contributionDays { date contributionCount contributionLevel weekday } } } } repositoriesContributedTo(first: 100, includeUserRepositories: false, contributionTypes: [COMMIT, ISSUE, PULL_REQUEST, PULL_REQUEST_REVIEW]) { totalCount nodes { nameWithOwner description url stargazerCount forkCount primaryLanguage { name } owner { login __typename } } } codeContributedTo: repositoriesContributedTo(first: 100, includeUserRepositories: false, contributionTypes: [COMMIT, PULL_REQUEST]) { nodes { nameWithOwner languages(first: 10, orderBy: {field: SIZE, direction: DESC}) { edges { size node { name } } } } } } byRepo: user(login: $login) { contributionsCollection { commitContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename } } contributions(first: 1) { totalCount } } issueContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename } } contributions(first: 1) { totalCount } } pullRequestContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename } } contributions(first: 1) { totalCount } } pullRequestReviewContributionsByRepository(maxRepositories: 100) { repository { nameWithOwner owner { login __typename } } contributions(first: 1) { totalCount } } } } }` -}} {{- else -}} {{/* kind "years": one aliased per-calendar-year block per contributionYears entry, count fields only. JSON-decoded numbers arrive as floats, so each year is cast to int before formatting; the cast is try-wrapped so a malformed remote value skips its block instead of failing the build. */}} {{- $blocks := slice -}} {{- range $years -}} {{- $y := 0 -}} {{- with try (int .) -}} {{- with .Value -}} {{- $y = . -}} {{- end -}} {{- end -}} {{- if and (ge $y 2005) (le $y 2100) -}} {{- $blocks = $blocks | append (printf `y%d: contributionsCollection(from: "%d-01-01T00:00:00Z", to: "%d-12-31T23:59:59Z") { totalCommitContributions totalIssueContributions totalPullRequestContributions totalPullRequestReviewContributions totalRepositoryContributions restrictedContributionsCount }` $y $y $y) -}} {{- end -}} {{- end -}} {{- $query = printf "query($login: String!) { user(login: $login) { %s } }" (delimit $blocks " ") -}} {{- end -}} {{- return (jsonify (dict "query" $query "variables" (dict "login" $login))) -}}
