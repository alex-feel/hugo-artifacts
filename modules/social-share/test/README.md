# social-share module validation suite

Playwright tests that validate the social-share module end to end against the minimal consuming site in [`fixture/`](fixture/). The fixture resolves the module from this repository checkout via `hugo.work` plus a `go.mod` `replace`, so no network module fetch is needed.

The fixture is exercised in three shapes: the SERVED site at a domain root, which the browser-driven specs drive, plus three STATIC builds under a `baseURL` that carries a path, which one spec reads straight off disk. The static builds exist because a domain root cannot tell a correct URL absolutization from a broken one -- Hugo's `absURL` discards the `baseURL` path for a value that starts with `/`, so at a root both the normalized and the unnormalized form emit identical bytes. The first two catch opposite mistakes: under `subpath.toml` (`baseURL = "http://localhost:1414/docs/"`) a consumer-authored site-root-relative value that LOST the `baseURL` path is visible, while under `schemeless.toml` (`baseURL = "/docs/"`) a Hugo-resolved value that GAINED it a second time is visible. The schemeless shape is the only one that can show the second mistake, because a scheme-carrying `.Permalink` is passed through untouched by the module's normalizer and so never reveals whether the normalizer would have mangled it. The third layers `canonify.toml` onto `subpath.toml`, adding `canonifyURLs` and nothing else. Hugo then absolutizes root-relative URLs in HTML output after the templates have run, and to stop the rewrite from doubling the base path it makes the `relURL` family stop emitting that path -- measured at v0.164.0, `relURL "img/share.png"` returns `/img/share.png` rather than `/docs/img/share.png`, while `absURL` is untouched and the module's normalizer is built on `absURL`. So the module's output must not move at all, and nothing would repair it if it did: the rewrite only reaches a root-relative value in an attribute ending in `href`, `src`, `srcset`, `action` or `url`, while every URL here is already absolute and most of it rides INSIDE another absolute URL, as a share intent's query parameter. A share target that lost the base path would be published exactly as written.

## What is covered

- `tests/01-markup.spec.js` -- server-rendered markup with JavaScript disabled: exact intent hrefs for the default list, the full encoding matrix (ampersand, percent, literal plus, emoji, quotes, angle brackets, a newline, a right-to-left override), the Mastodon fragment-only sharer, `safeURL` survival of `viber:`/`sms:` schemes, image-aware and instance-backed targets, the `images` front matter edge shapes (a map-shaped first entry falls through to the site-tier image; a literal filename carrying glob metacharacters resolves as a plain URL), a `networks_extra` endpoint that already carries a query, per-scheme `rel`/`target` policy, front matter overrides, the shortcode bar, and the pre-enhancement hidden state of the action buttons.
- `tests/02-enhancement.spec.js` -- progressive enhancement: capability-gated reveal of the copy and Web Share buttons, the `--enhanced` state class, the copy flow (clipboard content, live-region announcement, timed reset), rewiring of a bar restored from a DOM snapshot (Turbo/PJAX cache), and status-region emission rules.
- `tests/03-events.spec.js` -- the `social-share:share` and `social-share:action` CustomEvent surface, including that `detail.url` is the canonical page URL.
- `tests/04-subpath.spec.js` -- subpath deployment, read from the static builds in `fixture/public/subpath` and `fixture/public/schemeless` rather than from the server. Against the subpath build: every consumer-authored path that reaches the module's literal-URL fallback (`social_share.url`, `social_share.image`, the `images` front matter, the site-tier `params.social_share.image`) must keep the `baseURL` path, a `.Permalink`-derived URL must not be absolutized twice, a whitespace-only `social_share.url` must yield to the page permalink instead of emitting an empty share URL, and a whole-tree sweep asserts that no `data-share-url` or intent href anywhere in the build points at the origin root outside `/docs/`. Against the schemeless build: each page's default share URL carries the `baseURL` path exactly once, a consumer-authored value is still normalized, and a whole-tree sweep asserts no emitted share URL anywhere repeats the path as `/docs/docs/`. Both sweeps guard against passing vacuously -- the recursive directory walk must have descended, and the sweep must have inspected at least one share URL. Against the canonifyURLs build: every share URL a page emits is identical to the one the subpath build emits, page for page, and separately still carries the `baseURL` path exactly once, so the two builds agreeing by both losing it cannot pass; a consumer-authored site-root-relative image is checked by name, because it rides a query parameter of an already-absolute intent href and is the value with the least chance of being repaired. The control comes from the FIXTURE's own section listing rather than from the module: those links are authored root-relative, so the setting rewrites them and its absence leaves them alone -- without it the equality would pass against two identical builds.

## Running

Prerequisites: Hugo v0.160.0+ (any edition), Go 1.22+, Node.js 22+, and the Playwright Chromium browser (`npx playwright install chromium`).

```bash
cd modules/social-share/test
npm ci
./run-tests.sh        # or run-tests.cmd on Windows
```

The run script first builds the three static overlays (`hugo --config <chain> --destination public/<name>`, finite builds that bind no port; the chain defaults to `hugo.toml,<name>.toml` and is given explicitly where one overlay layers on another), fails the run on any deprecation or error in any log, then serves the fixture on port 1414 (override with `PORT`), fails the run if the server log mentions a deprecation, executes the suite, and always terminates the hugo server afterward. The overlay logs are kept at `hugo-build-subpath.log`, `hugo-build-schemeless.log` and `hugo-build-subpath-canonify.log` (gitignored) so a failure can be read after the fact.

The suite reaches all three trees through environment variables the run script exports: `FIXTURE_URL` for the served site, `FIXTURE_PUBLIC_SUBPATH` and `FIXTURE_PUBLIC_SCHEMELESS` for the static builds. To run against an already-running server and already-built overlays: `FIXTURE_URL=http://localhost:1414 FIXTURE_PUBLIC_SUBPATH=$PWD/fixture/public/subpath FIXTURE_PUBLIC_SCHEMELESS=$PWD/fixture/public/schemeless npm test`. Both directory variables default to `fixture/public/<name>` relative to the spec file, so they can be omitted when the overlays sit in their usual place.

[`fixture/subpath.toml`](fixture/subpath.toml) and [`fixture/schemeless.toml`](fixture/schemeless.toml) are the overlays: each differs from [`fixture/hugo.toml`](fixture/hugo.toml) in exactly one respect, its `baseURL` (`http://localhost:1414/docs/` and `/docs/` respectively), so any assertion difference between the trees is attributable to that alone. Adding another overlay takes three steps: drop `fixture/<name>.toml` in place, add one `build_overlay <name>` line to each run script, and export `FIXTURE_PUBLIC_<NAME>`.
