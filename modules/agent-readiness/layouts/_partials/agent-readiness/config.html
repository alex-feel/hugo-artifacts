{{/* agent-readiness/config.html -- INTERNAL (resolver tier). Purpose: resolves the module's entire configuration through the four-tier cascade, so every surface renders from one consistent dict and no downstream partial re-derives a value. Precedence, highest first: call-site args > page front matter (agent map) > site params ([params.agent]) > data/agent-readiness/defaults.toml. Presence wins at every tier (isset, not truthiness), so an explicit false or empty value overrides the tier below it. SITE-SCOPED keys are honored at the defaults and site tiers ONLY, because they shape site-wide artifacts (robots.txt, llms.txt, about.md, the skills index) that must select the same page set no matter which page renders them: `enable`, `sections`, `exclude_noindex`, `exclude_search_page`, `search_page_path`, `skills`, and the whole `robots` and `license` maps. The per-page opt-out is deliberately NOT one of these -- it is the page's own `agent: false` / `agent: {exclude: true}`, which the shared page filter honors on every surface at once. Nested maps merge tier by tier rather than replacing, so a consumer overriding one key inside [params.agent.markdown] keeps the shipped values for the rest. Hugo's merge is a recursive deep merge with the rightmost map winning, which is why each tier is merged on top of the accumulator in order. Slices are REPLACED by merge, never combined -- that is the intended semantics for every slice-valued key here (a consumer declaring `bots` means exactly those bots). Section identifiers are normalized through agent-readiness/lib/section.html, the ONE routine both the top-level allow-list and the per-entry [[llms.sections]] / [[facts.sections]] values pass through, so a bare name and a slashed form resolve identically at every call site. The per-entry values are normalized HERE and handed downstream already canonical, so no renderer re-derives them. Expected context (dict): - .page (Page) - The current page (already validated by the caller). - .args (map) - Call-site arguments (possibly empty). - .site_only (bool) - True when called from a site-wide artifact template (robots.txt): resolves the defaults and site tiers only and skips the page and call-site tiers entirely.
