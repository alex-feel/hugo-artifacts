{{/* agent-readiness/skills.html -- INTERNAL (resolver tier). Purpose: resolve the ordered slice of Agent Skills index entries, and manufacture the digest guarantee that makes the index worth publishing. THE DIGEST CONTRACT. Each entry's `source` is fetched at build time and REPUBLISHED same-origin -- a SKILL.md at /.well-known/agent-skills// SKILL.md, an archive at /.well-known/agent-skills/.tar.gz or .zip. The digest is then computed from the bytes of that published copy, not from an upstream snapshot, so the advertised hash and the served bytes can never disagree; there is no separate hashing step to fall out of sync. That is exactly what the discovery draft asks a digest to be for both distribution types: "For `type: "skill-md"`: the SHA-256 of the `SKILL.md` file's raw bytes. For `type: "archive"`: the SHA-256 of the archive file's raw bytes." An entry whose digest does not match the bytes an agent fetches FAILS CLOSED for any agent that verifies it, which is strictly worse than publishing nothing, so every failure path here omits the entry rather than guessing. BOTH DISTRIBUTION TYPES. The draft defines `type` as "MUST be `"skill-md"` (single `SKILL.md` file) or `"archive"` (bundled archive)", and a skill that ships supporting files belongs in an archive: its `SKILL.md` addresses them by relative path, and those paths resolve to nothing at all under a republished single file. Hugo has no build-time archive writer -- and no bitwise primitives with which to hand-assemble one -- so an archive is FETCHED already built and republished byte for byte, exactly as a SKILL.md is. What the module can then check, it checks; what it cannot see inside the archive, the README states plainly is the publisher's to guarantee. WHAT THE BYTES DECIDE. The published extension is chosen from the artifact's magic number rather than from the source URL or the response header, because resources.Copy keeps the source's media type whatever the target is named, so a mislabelled entry would otherwise publish a gzip stream at a `.zip` path with nothing to say so. A declared type that the bytes contradict is refused in both directions. SUPPORTING FILES, VERIFIED RATHER THAN GUESSED. A `skill-md` entry whose body appears to reference sibling files has those references RESOLVED against its own source URL and probed. A sibling that really exists proves the skill is multi-file, and the entry is reported -- warned about by default, omitted when the consumer sets skills_index.on_supporting_files to "omit". The default is to warn AND publish because the detector is best-effort by construction: it can only nominate names the body itself mentions, and a heuristic must not be able to delete a whole .well-known surface, which is what refusing the last surviving entry would do. Field validation runs before the fetch wherever it can, so a malformed entry costs no network round trip: `name` is 1-64 characters of lowercase alphanumerics and hyphens with no leading, trailing or consecutive hyphen (it becomes a published path segment); `type` is "skill-md" or "archive"; `source` must be absolute. `description` is checked against the 1-1024 character rule wherever it is finally resolved -- for a `skill-md` entry it may be omitted and taken from the fetched front matter, which the draft says it SHOULD match anyway, and that value only exists after the fetch. Pin every `source` to a COMMIT SHA or an immutable release URL, never a branch ref: a branch moves, and a moved branch means the digest published last build describes bytes that have since changed. Expected context (dict): - .page (Page) - The home page. - .cfg (dict) - The resolved config from agent-readiness/config.html. Return value: the ordered slice of validated, fetched, published entry dicts (possibly empty). ONE terminal return. */}} {{- $cfg := .cfg -}} {{- $entries := slice -}} {{- $strict := eq (printf "%v" ($cfg.skills_index.on_supporting_files | default "warn")) "omit" -}} {{/* How many sibling probes one entry may spend. Hitting it is reported rather than absorbed. */}} {{- $probeLimit := 4 -}} {{/* Names must be unique because each one is the sole path segment its artifact is republished under.
