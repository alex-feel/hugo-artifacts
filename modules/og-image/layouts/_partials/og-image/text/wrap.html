The function is TOTAL: it returns at most max_lines lines for EVERY input, with overflow=true when content had to be dropped. That is what lets the fitter treat the shrink ladder as "the first rung whose overflow is false" and still hold a usable answer when no rung fits. A word wider than the budget is hard-split. A hard break flushes the current line even when it is empty, so an author's blank line survives. Truncation keeps the LONGEST PREFIX of the last allowed line that leaves room for the ellipsis -- accumulated width is monotonic, so one forward pass finds it -- and when not even the first piece fits, that piece is itself split against budget minus the ellipsis width, so a single over-long word truncates to a readable head plus the ellipsis rather than to a bare ellipsis.
