# og-image module validation suite

Build-output assertion tests that validate the og-image module against the minimal consuming site in [`fixture/`](fixture/). The fixture resolves the module from this repository checkout via `hugo.work` plus a `go.mod` `replace`, so no network module fetch is needed.

The module's output is a RASTER, which is what makes this suite different from the other module suites in this repository. A card that exists, is the right size and is referenced from the right page can still be blank, drawn on the wrong backdrop, carrying the wrong words, wrapped to the wrong number of lines, or invisible because Hugo silently drew an unreadable color as white. So the specs decode the published PNG and JPEG bytes and assert what was actually drawn: the format and dimensions come from the file header, the composited background from a corner pixel, the number of drawn lines from contiguous runs of rows carrying ink, the fitted size and the resolved line height from the distance between those runs, which face drew a line from the extent of its ink, the drawn string from a calibrated monospace advance, the ink color from the most fully covered pixel, and the overlay's placement from the exact bounding box of a color that appears nowhere else on the card.

The measuring instrument is [`tests/lib/raster.js`](tests/lib/raster.js), about two hundred lines over `node:zlib` with no dependency, and [`tests/00-instrument.spec.js`](tests/00-instrument.spec.js) tests it against the fixture's committed rasters and a hand-built pixel buffer before any card is read. A broken decoder would make every other assertion pass or fail for the wrong reason, which is indistinguishable from a suite that works. Golden-image diffing is deliberately not used: a golden fails on any antialiasing or encoder change, says nothing about WHICH property broke, and has to be regenerated by the code it is meant to check.

The module ships zero JavaScript, so there is no browser behavior to test. The suite uses Node's built-in test runner (`node --test`) with `node:assert` and `node:zlib` only, so it needs no `npm install`, no lockfile and no `npm ci`.

## How a page's card is observed

A Hugo template cannot hand a value to a test, so the fixture writes one down. [`layouts/_partials/fixture/record.html`](fixture/layouts/_partials/fixture/record.html) calls `og-image/card.html` exactly as a consumer does and publishes a JSON sidecar per page at `cards/<language>/<page path>/payload.json`, recording the page's identity, the strings the module was handed, the scalar half of the options it resolved, and every card it returned. The home page separately writes `inventory/<language>/pages.json` out of Hugo's own page set, so the "a declining page produces no card" assertion is made against everything Hugo built rather than against a list someone remembered to update, and `crosslang/<language>/pages.json`, which is where the multilingual lock lives.

The recorder chooses among the entry's three call shapes from front matter, because the entry treats them differently: a bare Page (the standalone call, so the module derives the title and description itself), the `{page, title, description}` dict the generated-image hook uses, and a second call carrying an `opts` variant and template, which is how one page carries more than one card. The page `blog/handed-vs-title.md` carries a two-character `.Title` while the recorder hands the module a twenty-character string, and that is the only shape in the suite that can tell a module honoring the handed strings from one re-deriving the page title.

## The environments

Eight builds. Each earns its place by a distinction no other one can make.

| Build | Flag | The distinction only this build can make |
| --- | --- | --- |
| `baseline` | none | `[params.ogcard]` entirely ABSENT -- the only build that can tell "inert when unconfigured" from "works". A TOML overlay can add a table but never delete one, so the unconfigured state has to be `config/_default` and every working configuration lives in `config/<environment>/`. |
| `configured` | `-e configured` | The working card set. The ONLY build whose log must be silent, and where every positive assertion lives. |
| `degraded` | `-e degraded` | Every fault class at once, each on its own section, template or slot, so N distinct faults must produce N distinct diagnostics and none may mask another -- provable only together, and unmergeable with `configured`, which has to stay quiet. |
| `multilingual` | `-e multilingual` | A card composed for a page of one language while ANOTHER language is rendering, which is the only shape in which a configuration read through the page's own language and one read through the rendering language give different answers. Also the only build in which two languages carry two different bad values, and in which per-language card identity and the shared derivative directory are visible. |
| `subpath` | `-e subpath` | A `baseURL` carrying a PATH. At a domain root a card URL that keeps the base path and one that drops it are byte-identical, so this is the only build in which the difference exists at all. |
| `subpath-canonify` | `-e subpath --config ../canonify.toml` | That same `baseURL` with `canonifyURLs = true`. Hugo then absolutizes root-relative URLs in HTML output after the templates have run, and to stop the rewrite from doubling the base path it makes the whole Page family stop emitting it: measured at v0.164.0, a page's `.RelPermalink` comes back as `/blog/short/` rather than `/docs/blog/short/`. A RESOURCE's does not, and `.Permalink` is untouched. This module states its card URL off the processed image resource and absolutely, so both builds must publish the same URLs -- the property this build LOCKS rather than a defect it hunts. What it would catch is a card URL routed through the `relURL` family: still correct wherever it rode an `href`, because the post-processor repairs those, and wrong where this module actually puts it, since `og:image` and `twitter:image` are meta `content` attributes the rewrite never reaches. The subject that makes the comparison assertable is the fixture payload's own `url` field, which is the PAGE URL and therefore DOES move; without a value that moves, "the two builds agree" would pass against two ordinary builds. |
| `routing` | `-e routing` | `default_template`, the routing tier for a page NO route names, plus the whole precedence walk above it. It cannot live in `configured`, whose documented decline set is the proof of the opposite statement -- that an unnamed page gets nothing at all. Both claims are true of the module and only one can be true of a build. Warning-gated like `configured`. |
| `typography` | `-e typography` | The only build whose MODULE level names a face, a width table and a line height. Typography resolves as text slot > card template > module level, and in `configured` every slot names its own face -- so nothing there can tell a value a slot supplied from one the site supplied. `configured` in turn has to keep naming none of the nine, because that absence is what makes its `unstyled` card a statement about what the module SHIPS. |

The fault environment cannot put its faults in front matter, because content is shared across all eight builds and `configured` has to stay silent. Every `deg-*` section is therefore unrouted in `configured` -- a silent decline -- and routed to a deliberately broken template in `degraded`. The typography environment works the same way from the other side: it routes sections the other builds already carry to probe templates of its own, so proving a three-level cascade costs a config file and no content.

## What is covered

- [`tests/00-instrument.spec.js`](tests/00-instrument.spec.js) -- the decoder itself: header sniffing of PNG, the loud failure on a file that is not an image, a three-channel and a four-channel decode against known flat colors, and the band, bounding-box, ink-color and character-count functions against a hand-built canvas whose every number is readable in the source.
- [`tests/01-card.spec.js`](tests/01-card.spec.js) -- what a card IS: a real file at the published URL, 1200x630 read from the file HEADER rather than from the Resource (a module that returns 1200x630 and draws 1200x628 fails only here), the Resource's own dimensions and media type agreeing with the bytes, the card-bearing page count asserted EXACTLY rather than as a floor, non-page kinds still served, and one page carrying two cards told apart by variant.
- [`tests/02-base-selection.spec.js`](tests/02-base-selection.spec.js) -- WHICH background was composited, from both corners: every fixture backdrop is a distinct flat color, so a route that quietly sent every page to one template is visible here and nowhere else. Includes the 800x400 backdrop normalized up to the canvas, and the call-tier template answering for a page's second card.
- [`tests/03-text.spec.js`](tests/03-text.spec.js) -- WHAT was drawn: the monospace advance calibrated in-build from a title of known length, then every monospace card's glyph count compared with the string it was given; the handed-versus-derived title discriminator; both slots drawn in their own configured colors; an OpenType face drawing at its own widths rather than falling back; and Cyrillic and Greek producing real ink inside the box.
- [`tests/04-wrapping.spec.js`](tests/04-wrapping.spec.js) -- the text engine, locked to arithmetic: exact line counts for the one-, two- and three-line pages derived from the 26-glyph budget; the size the shrink ladder settled on, recovered from the pitch between band tops; the overflow page capped at `max_lines` at the floor rung; a ninety-character unbreakable token hard-split inside the box; the whole-tree promise that no wrapped line runs past the box it was given; and the description slot wrapping against its own narrower box and its own line bound.
- [`tests/05-overlay.spec.js`](tests/05-overlay.spec.js) -- the overlay's exact rectangle, which is the anchor arithmetic read back: `(1200 - 80) - 48` and `(630 - 80) - 48`; zero badge-colored pixels anywhere outside it; the same placement on every card of that template; the negative control of a template with no overlay at all; and an overlay wider than the canvas clipped silently with the card still published.
- [`tests/06-decline.spec.js`](tests/06-decline.spec.js) -- declining publishes nothing and says nothing: every page Hugo built is either carded or in the documented decline set, the front-matter off switch is distinguished from an unrouted section by the resolved options, a page writing its own `ogcard` map loses a cascaded one wholesale while its sibling keeps it, and no derivative sits in the tree that no page received.
- [`tests/07-degraded.spec.js`](tests/07-degraded.spec.js) -- every deliberate fault at once, each with the diagnostic it emits AND the pixel-side consequence beside it: an unreadable color still drawing the card in the white Hugo falls back to, a font file that is not a font costing the face and not the card (measured as a wider ink run), background faults declining the whole card while overlay faults drop one overlay, a `text` key Go could not range over declining instead of stopping the build, and rejected module-level values falling back to the shipped mechanical ones.
- [`tests/08-inert.spec.js`](tests/08-inert.spec.js) -- the unconfigured site: no page carded, no image file anywhere in the tree (composed-then-discarded cards included, which a page's record could not show), the shipped mechanical defaults still resolving, and exactly the diagnostics an unconfigured site can earn.
- [`tests/09-multilingual.spec.js`](tests/09-multilingual.spec.js) -- per-language configuration: each language's own backdrop, a card composed under a FOREIGN rendering language still reading its own language's configuration, a language that overrides part of the table inheriting the rest, translations with different content getting different cards, derivatives published once at the site root, and two different bad values in two languages both reported.
- [`tests/10-subpath.spec.js`](tests/10-subpath.spec.js) -- a `baseURL` carrying a path: every card URL carries the base path exactly once and names a file that is really at that address, and the same content set declines and cards exactly as it does at a domain root.
- [`tests/11-format.spec.js`](tests/11-format.spec.js) -- the encoded format from the frame header rather than from the extension, the media type and the resolved options agreeing with it, a comparative quality assertion between two sections cascading the same template and title at two qualities, and every lossless card in the tree sniffing as an 8-bit non-interlaced PNG.
- [`tests/12-determinism.spec.js`](tests/12-determinism.spec.js) -- a card as a function of its inputs: two pages with identical content resolving to the identical file, one character of difference resolving to a different file with different bytes, the two calls a page receives per build resolving to one card, and the same title on two templates being two cards.
- [`tests/13-readme.spec.js`](tests/13-readme.spec.js) -- documentation and data locks: the shipped defaults file carrying the mechanical values and no design value, the width table's keys matching what the text engine reads, every option in the module's surface being read by the template that owns it, and the README naming every option, every text source token, every shipped default value and the Hugo version the module declares.
- [`tests/14-sources.spec.js`](tests/14-sources.spec.js) -- WHERE a slot's text comes from: the nine source tokens that read the page, the site, the clock and the data directory rather than the caller (`title` and `description` are the caller's, and belong to `03-text`), each drawn as its own monospace row whose ink extent divided by the calibrated advance is a character count; the four case transforms; a prefix and suffix that are dropped with the value they were glued to when it resolves empty; and the flat-list rule -- a `data` or `param` list drawing one item per line at the resolved pitch, with a dotted `data` path through a scalar drawing nothing at all.
- [`tests/15-routing.spec.js`](tests/15-routing.spec.js) -- the fourth routing tier and the precedence walk above it, each tier answered by a template with its own flat backdrop so which candidate won is a corner pixel rather than an inference: front matter beats a section route, a section route beats a kind route, a kind route beats `default_template`, and a page switched off in front matter still gets none of them.
- [`tests/16-meta.spec.js`](tests/16-meta.spec.js) -- the module's SECOND public entry, read out of the published HTML: `og-image/meta.html` is the only part whose product is markup, the fixture's head calls it on every page, and until this spec existed its tags could have been absent, relative or duplicated with every other assertion here green.
- [`tests/17-typography.spec.js`](tests/17-typography.spec.js) -- the three levels a site sets its type at, told apart from each other in pixels: a face and a line height named once at the module level reaching slots of two different templates that name neither, a card template outranking the module level, one slot outranking its card template on the same card, the width table travelling with the face at all three levels (two slots in one face and one box breaking their lines in different places is the mistake the cascade exists to prevent), a bad value at each level warning once and falling back to the LEVEL below rather than to a fixed value, and -- from the build whose module level names none of the nine -- a slot naming none of them anywhere still drawing, in Hugo's own built-in face at the one line height the module ships.
- [`tests/18-canonify.spec.js`](tests/18-canonify.spec.js) -- the subpath environment rebuilt with `canonifyURLs` on, the one setting under which a card URL derived from the `relURL` family reads correctly everywhere except where this module puts it. Hugo repairs a stripped root-relative URL in attributes ending in `href`, `src`, `srcset`, `action` and `url`, and in nothing else -- so `og:image` and `twitter:image`, being meta `content` attributes, would carry the loss to every crawler that fetches them. The module reads its URL off the image resource and states it absolutely, so the assertions are equalities against the build without the setting, card for card, plus a resolution of every URL against this build's own tree so that both builds losing the path could not pass. The control is the fixture payload's `url` field, which is the PAGE URL and moves under the setting exactly as much as the card URLs must not.

## Running

Prerequisites: Hugo v0.160.0+ (the suite is run on the extended edition; a non-extended binary is untested), Go 1.22+, Node.js 22+. No `npm install` step: the suite has no dependencies.

```bash
cd modules/og-image/test
./run-tests.sh        # or run-tests.cmd on Windows
```

The runner removes `fixture/public` outright before building rather than relying on `--cleanDestinationDir`, which only drops files absent from the static directories: a card a previous build published and this one does not would otherwise survive into the tree the specs read, and this suite's central negative assertion is "a declining page produces NO card", which stale bytes satisfy silently.

It then performs eight builds with `hugo --logLevel info` (builds, not a server -- no port binding), each hard-failing if its log carries any deprecation or error line, and additionally fails the `configured` and `routing` builds on any warning at all. The other six builds carry the diagnostics they exist to produce, and the specs assert them -- the typography build line for line, which is what lets positive assertions live in a build the runner does not gate on silence. Finally it exports `FIXTURE_DIR`, `MODULE_ROOT`, one `FIXTURE_PUBLIC_*` directory and one `HUGO_BUILD_LOG_*` file per environment, and `HUGO_VERSION`, then runs `npm test` (`node --test "tests/*.spec.js"`).

To re-run the specs against an already-built fixture, export the same variables and run `npm test` directly; the logs are retained after a successful run (they are gitignored at the repository root) so the warning assertions can read them without rebuilding.

## How the faults are counted: by class, and again by line

`tests/07-degraded.spec.js` asserts four things: every fault has a diagnostic, no diagnostic is unaccounted for, the number of distinct fault classes equals the number of faults, and each of those faults was reported exactly ONCE rather than once per page that hit it.

The line count is the sharper of the two instruments, and it is assertable at all because of how the module deduplicates. `lib/warn.html` wraps `lib/warn-emit.html` in `partialCached` keyed on the warning key, and that cached body reads a build-scoped `hugo.Store` sentinel and then writes it. The sentinel on its own is a read and a write while Hugo renders pages concurrently, so several pages could pass the read before any of them wrote and one mistake would print once per racer; `partialCached` is what serializes them, and the sentinel is what collapses the per-language repetition `partialCached` leaves behind, since it keeps one cache per language. A regression in either is invisible to a class count -- every class is still present -- and surfaces only as a line count that drifts between otherwise identical builds.

A site-level mistake is attributed to the configuration that carries it rather than to a page: `config.html` names the tier every value came from and folds that name into the dedup key, so the message reads `set in params.ogcard for language "en"` and cannot key itself per page.

## Third-party assets

This suite is the first place in this repository to commit a font. The repository's own license covers the repository's code, not a vendored binary, so each font sits beside the full text of its own license under [`fixture/assets/fonts/`](fixture/assets/fonts/).

| File | Bytes | Upstream | Upstream path | Revision | License |
| --- | --- | --- | --- | --- | --- |
| `Go-Mono.ttf` | 173248 | `golang.org/x/image` | `font/gofont/ttfs/Go-Mono.ttf` | v0.18.0 | BSD-3-Clause, copyright 2016 Bigelow & Holmes Inc.; full text in `Go-Mono-terms.txt` |
| `SourceSans3-Regular.otf` | 334924 | `github.com/adobe-fonts/source-sans` | `OTF/SourceSans3-Regular.otf` | 3.052R (commit `87b37a2daaed80fcb8e8ccb0085c4d72ddade12e`) | SIL Open Font License 1.1; full text in `SourceSans3-Regular-terms.txt` |

Both files are committed byte-for-byte as upstream publishes them; neither is subset, renamed inside its own name table, or otherwise modified.

Go Mono is the monospace face every text assertion rests on. A monospace advance is what turns an ink extent into a character count, and Go Mono advances every glyph by 1229/2048 of the em, so the 600-per-mille width table in [`fixture/data/og-image/metrics-local.toml`](fixture/data/og-image/metrics-local.toml) describes the whole face to within a thousandth of an em and every expected line count becomes arithmetic. The `wide` table beside it models nothing real and exists for one assertion: at twice the monospace width, a box that takes two words under `mono` takes one, so two slots drawn in the SAME face and the same box can still break their lines in different places -- which is how the width table that travels with a face is measured. It is also the family Hugo already embeds as its built-in face, so committing it adds no licensing posture the module did not already have. Source Sans 3 exists for one assertion: the module's font guard admits OpenType while Hugo's own documentation lists it as unsupported for `images.Text`, and the `configured` build is warning-gated, so the card either draws in that face or the suite goes red.

`broken.ttf` and `webfont.woff2` are thirty-two bytes of text each. The first has a correct extension and no font inside, which fails the whole filter chain at the `images.Filter` call and is what the module's safety net exists to catch; the second is rejected by extension before it is ever read.

The other committed fixture assets are machine-generated flat single-color rasters -- `og/home-bg.png`, `og/post-bg.png`, `og/de-bg.png`, `og/wrong-size.png`, the 80-pixel `og/badge.png`, the `og/param-badge.png` an overlay reaches through a front-matter key, and the `content/overlays/bundled/avatar.png` an overlay reaches as a page resource -- plus `og/not-an-image.png`, which is forty bytes of text carrying an image extension. They are committed rather than generated at test time on purpose: a generator is a second artifact that has to be right itself, and an input produced by this repository's own code can pass because the generator and the module share a wrong assumption. The distinct flat color per raster is what makes the corner-pixel background assertion possible, and the flat fill is what makes an ink pixel unambiguous.
